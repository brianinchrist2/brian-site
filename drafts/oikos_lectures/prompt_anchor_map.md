# 任务：给全书大纲的每个要点指定它在正文里的落点小节

## 输入
`anchor_map_input.json`（在当前工作目录下），结构：

```
{"chapters":[
  {"ch":"preface","key":"前言：教会论本体的回归",
   "headings":[{"aid":"h1-写作立场与神学溯源","text":"一、写作立场与神学溯源"}, ...],
   "points":[{"pid":"0-0","title":"唯独圣经的彻底态度","summary":"..."}, ...]}, ...]}
```

- `headings` 是该章**正文里真实存在的小节标题**，按正文顺序排列；`aid` 就是正文渲染时该标题的锚点 id。
- `points` 是该章在导图里的要点（标题 + 一句话小结）。
- 共 22 章、110 个要点。

## 要做的事
给每一个 `pid` 挑一个 `aid`，表示「点这个要点应该跳到正文的哪一节」。

规则：
1. `aid` 必须是**同一章** `headings` 里真实存在的值，**逐字复制**，不许改写、不许拼造、不许跨章。
2. 以**标题语义**为主判断，`summary` 作为补充，选语义上最贴近该要点的那一节。
3. 若一个要点是整章的总述、横跨多节、或与该章任何小节都不贴合 → `aid` 填 `"chapter"`（表示跳到该章开头）。
4. 多个要点可以用同一个 `aid`；不要求一一对应。

## 输出
严格 JSON（单个文件 `anchor_map.json`，不要写别的文件，不要有注释或多余文字）：

```json
{"mapping":[{"pid":"0-0","aid":"h1-写作立场与神学溯源","why":"≤10字"}, ...]}
```

## 硬性要求
1. **覆盖全部 110 个 pid**，一个不落，顺序与输入一致。
2. `aid` 会被程序逐条比对：不属于该章 headings 的值视为错误。
3. 不要修改任何 `title`/`summary`，不要新增字段。
4. 只输出 `pid`/`aid`/`why` 三个字段。
